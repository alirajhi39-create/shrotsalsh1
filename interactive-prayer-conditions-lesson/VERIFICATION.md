## 1) ما تم تنفيذه

### البنية التقنية
| العنصر | التنفيذ |
|---|---|
| الإطار | Next.js 16 (App Router) + TypeScript + Tailwind CSS v4 |
| قاعدة البيانات | PostgreSQL عبر Drizzle ORM — يختار السائق تلقائيًا: `@neondatabase/serverless` (HTTP) عندما يشير `DATABASE_URL` إلى Neon، و`pg` لأي PostgreSQL آخر (`src/db/index.ts`) |
| التحقق من المدخلات | Zod في جميع مسارات API |
| المصادقة | معلم: كلمة مرور فقط (scrypt) + كوكي موقّع HMAC (httpOnly). طالب: رمز جلسة عشوائي 256-bit يُخزَّن مجزّأً (SHA-256) في `student_sessions` + رمز استكمال (6 رموز) للمتابعة من جهاز آخر، مع نسخة احتياطية من رمز الجلسة في المتصفح تُرسل في ترويسة Authorization عندما تُحجب الكوكيز |
| الكوكيز داخل الإطارات | عبر HTTPS تُضبط الكوكيز بـ `SameSite=None; Secure; Partitioned`. إذا حجبها المتصفح يستخدم الطالب رمز الجلسة في `Authorization` مع hash لا يُرسل للخادم، ويستخدم المعلم API لتسجيل الدخول ورمزًا موقّعًا في `Authorization`/`auth` مع `src/proxy.ts`؛ يستمر ذلك في RSC وServer Actions وإعادة التحميل. لا يظهر رمز المعلم في الرابط إلا بعد فشل فحص الكوكي فعليًا |
| تهيئة المخطط | `src/db/bootstrap.ts` ينشئ الجداول والفهارس تلقائيًا إن لم تكن موجودة (نشر جديد بدون تنفيذ الهجرات يدويًا) |
| الهجرات | `drizzle/0000_init_shurut_alsalah.sql` + `drizzle.config.ts` (يقرأ `DATABASE_URL_UNPOOLED` ثم `DATABASE_URL`) |
| البذر (Seed) | `src/lib/seed.ts` — يعمل تلقائيًا عند أول طلب، آمن للتكرار (`ON CONFLICT DO NOTHING`) ولا يمس تعديلات المعلم |
| اللغة والاتجاه | عربية كاملة، `dir="rtl"`، خط Cairo (+Amiri للنص القرآني) |

### الجداول (16) — كلها مُنشأة ومستخدمة فعليًا
`teachers, classrooms, students, lessons, lesson_slides, activities, questions, student_sessions, student_progress, student_answers, quiz_attempts, achievements, certificates, audio_recordings, teacher_settings, audit_logs`
مع مفاتيح أساسية/أجنبية، قيود فريدة (مثل `student_answers(student, lesson, slide, activity, attempt)` و`idempotency_key`)، وفهارس.

### إصلاح الكوكي القديم وكلمة المرور
- كان الكوكي القديم/الملغى يُجرّب أولًا ثم يمنع استخدام رمز الجلسة الجديد؛ أصبح النظام يجرّب `Authorization` تلقائيًا عند فشل الكوكي للطالب والمعلم.
- اختُبر `Cookie` تالف مع رمز طالب صحيح: `200` وظهرت بيانات الطالب، ومع المعلم: فتحت اللوحة بنجاح. الكوكي التالف وحده ما زال `401`.
- تغيّرت كلمة مرور المعلم في قاعدة البيانات إلى `139613`؛ الجديدة `200` والقديمة `401`.
- اختبار Chromium مع كوكيز تالفة مزروعة مسبقًا: الطالب دخل وحفظ نشاطًا وأعاد التحميل دون الخروج، والمعلم دخل بالكلمة الجديدة، والقديمة أظهرت رسالة الرفض، ولا أخطاء Console.

### اختبار متصفح حقيقي (Chromium) لمشكلة الدخول
- دخول طالب بالنقر الفعلي ثم فتح `/lesson` وظهور اسمه ومحطاته: ✅ في الصفحة العادية وداخل iframe.
- دخول المعلم بكلمة المرور فقط ثم فتح `/teacher` والتنقل إلى الطلاب والإعدادات: ✅ بلا أخطاء Console.
- محاكاة رفض الكوكيز والتخزين المحلي واسم النافذة: الطالب تابع الدرس وحفظ نشاطه ثم أعاد تحميل الصفحة دون فقدان الجلسة عبر `#s=` ✅.
- محاكاة رفض كوكي المعلم: فُعّل مسار `?auth=` تلقائيًا، وعمل التنقل وإعادة التحميل وحفظ الإعدادات (Server Action) ثم تسجيل الخروج ✅.
- الوضع العادي للمعلم يبقى بعنوان نظيف بدون `auth` ✅.
- الوصول المباشر إلى `/teacher?auth=invalid` بدون كوكي مرفوض ويحوّل لتسجيل الدخول ✅.

## 3) ما يحتاج إعدادًا خارجيًا (لم يكن متاحًا في هذه البيئة)

لا توجد صلاحيات Vercel أو Neon في بيئة التطوير، لذلك **لم يتم النشر فعليًا** ولم يُنشأ مشروع Neon. قاعدة البيانات المستخدمة أثناء التطوير هي PostgreSQL محلية (`127.0.0.1`) وليست قاعدة إنتاج. خطوات الربط:

1. **Neon عبر تكامل Vercel الرسمي:** من لوحة Vercel → Storage → Create Database → Neon. سيُضاف تلقائيًا `DATABASE_URL` (pooled) و`DATABASE_URL_UNPOOLED`.
   أو يدويًا: أنشئ مشروع Neon وأضف المتغيرين في Vercel → Settings → Environment Variables.
2. أضف `AUTH_SECRET` (مثال: `openssl rand -hex 32`) و(اختياريًا) `TEACHER_USERNAME` / `TEACHER_PASSWORD`.
3. طبّق المخطط على Neon مرة واحدة من جهازك:
   ```bash
   DATABASE_URL_UNPOOLED="postgresql://...neon.tech/neondb?sslmode=require" npx drizzle-kit push
   # أو: npx drizzle-kit migrate   (يستخدم drizzle/0000_init_shurut_alsalah.sql)
   ```
4. انشر: `vercel --prod` (أو عبر ربط المستودع). عند أول طلب يُنفَّذ البذر تلقائيًا (الدرس، 12 محطة، 18 نشاطًا، 19 سؤالًا، الفصلان الثالث (أ) و(ب)، المعلم الافتراضي).
5. تحقق: `GET /api/health` يجب أن يعيد `{"ok":true}`، ثم سجّل طالبًا تجريبيًا وتأكد من ظهوره في `/teacher/students`.

**دخول المعلم:** بكلمة المرور فقط (بدون اسم مستخدم). كلمة المرور الافتراضية: `139613` — غيّرها فورًا من الإعدادات.

**الموقع المرجعي (إيتاء الزكاة):** هذا المشروع مستقل في مستودع/قاعدة مختلفة ولم يُلمس الموقع المرجعي أو بياناته. إذا رغبت باستضافة الدرسين على قاعدة Neon واحدة فالمخطط يدعم تعدد الدروس (`lessons.slug`) دون تعارض في الجداول.

## 4) ملاحظات المحتوى
- النصوص الدينية منقولة من صور الكتاب بالتشكيل: حديث «لا يقبل الله صلاة أحدكم إذا أحدث حتى يتوضأ» (مسلم 225)، حديث «رفع القلم عن ثلاثة…» (أبو داود 4403، الترمذي 1423)، والآية ﴿يَا بَنِي آدَمَ خُذُوا زِينَتَكُمْ عِندَ كُلِّ مَسْجِدٍ﴾ [الأعراف: 31].
